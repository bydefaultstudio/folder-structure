# Project Brief — Folder Structure

**Project name:** folder-structure

---

## 1. Project Summary

**In one sentence:**
A public web tool for visualising folder structures as an interactive tree — paste code or text to auto-generate a diagram, or build one manually, then copy out clean, AI-ready text describing the structure.

---

## 2. Problem & Opportunity

**Problem**
Describing a folder structure to an AI tool (Claude, etc.) or to a teammate in plain text is fiddly and error-prone — indentation breaks, formats vary, and it's hard to see the shape of what you're describing.

**Opportunity**
A visual editor and generator makes the structure unambiguous: see it as a tree, edit it directly, and export a clean text representation any AI tool can understand and act on.

---

## 3. Goals

**Primary goals**
- Paste code/text and auto-generate an interactive folder-tree diagram
- Manually build and edit a structure — add folders/files, rename, nest
- Generate and copy clean text output to paste into Claude or other AI tools so they understand the folder structure you want created

**Secondary goals**
- Usable by clients and teams, not just developers
- A small public showcase of By Default's design system and craft

---

## 4. Non-Goals (Out of Scope)

- No user accounts or saving — everything is client-side
- No backend at all — pure static HTML/CSS/JS
- No shareable URLs encoding a structure (could come later)
- No file/folder uploads — text input and manual editing only

---

## 5. Audience

**Primary audience**
Public — anyone who needs to communicate a folder structure, especially people working with AI coding tools.

**Secondary audience**
By Default's own team and clients.

---

## 6. Success Criteria

- Pasting a structure (ASCII tree, indented text, or file paths) renders the correct interactive tree
- Manual editing (add / rename / nest / delete) is fast and intuitive
- The copied text output is unambiguous and works when pasted into Claude
- A working v1 ships within days

---

## 7. Constraints & Requirements

**Timeline**
ASAP — a usable version within days.

**Platforms**
Responsive web (desktop-first workflow, works on mobile).

**Technical constraints**
- Static site built from the studio template (HTML/CSS/JS, design system via `@bydefaultstudio/design-system`)
- Hosted on Cloudflare Pages (build command `npm install`, publish directory `/`)
- No backend, no database

**Accessibility**
Keyboard-navigable tree with proper ARIA (template standard).

**Performance**
Lightweight static site — no heavy dependencies.

---

## 8. Design & Build Notes

**Design system**
Shared design system with By Default studio brand overrides in `assets/css/theme.css` (Zalando Sans, IBM Plex Mono, warm palette, accent ramps).

**Content**
Minimal copy — the tool's content is generated by the user. Interface copy written during build.

**Known risks**
- Input parsing: pasted structures come in many formats (ASCII tree characters, plain indentation, path lists) — parser needs to be tolerant
- Output format needs to be a spec Claude/AI tools reliably interpret

---

## 9. Open Questions

- Which input formats to support at launch (ASCII tree, indentation, path list — all three?)
- Exact output format (ASCII tree vs. markdown list vs. both)
- Final domain (placeholder: folder-structure.pages.dev until connected)
